# Шаг 14. Веб-клиент и продуктовые числа

## Что нужно сделать

Клиент уже умеет показывать каталог, собирать корзину, оформлять заказ и
показывать его статус: витрину отдаёт каталог, заказ создаёт сервис заказов,
экран собирает BFF одной ручкой. Не хватает второй половины: **чисел о том, как
люди по этому пути идут**.

Воронка покупки состоит из четырёх шагов:

```
увидел карточку -> положил в корзину -> начал оформление -> оплатил
```

Нужно:

1. **Отмечать шаги** в компоненте `Shop`: показ карточек, добавление в корзину,
   начало оформления и оплату. Последний шаг считается по **реальному статусу
   платежа**, а не по нажатию кнопки: нажали не значит заплатили. Это главная
   ошибка в продуктовой аналитике: считать намерение вместо результата.
2. **Считать конверсию** в `conversion()`: сколько дошло до каждого шага и какая
   это доля от предыдущего. Шаг, до которого не дошёл никто, не должен делить
   на ноль.

## Как проверить себя

Нужен Node.js 20 или новее.

```bash
cd web
npm install
npm test
```

Красные три проверки: `считает долю дошедших до каждого шага` и `шаг, до которого
никто не дошёл, не делит на ноль` в `src/__tests__/funnel.test.ts`, `путь покупки
виден в воронке целиком` в `src/__tests__/shop.test.tsx`. Остальные четыре
(запись шага с товаром и временем, каталог и счётчик корзины, оформление с ключом
идемпотентности, пустая корзина) зелёные и такими должны остаться. Сеть подменена
заглушкой, браузер не нужен.

## Посмотреть глазами

Стенд `docker compose -f ../infra/compose.yaml up -d`, затем из одного окружения
четыре сервиса, каждый из своей папки в `services/`:

```bash
uvicorn catalog.main:app --port 8180
uvicorn order.main:app --port 8181
uvicorn payment.main:app --port 8186
uvicorn bff.main:app --port 8190
```

и `npm run dev` в `web/`. Vite в разработке играет роль шлюза: `/api/v1/products`
уходит в каталог, `/api/v1/orders` в заказы, `/api/v1/screens` в BFF (порты в
`vite.config.ts`). Товар на витрине появляется после публикации продавцом, как в
`README.md` каталога.

## На что посмотреть по дороге

- Сравни числа: 10 просмотров, 4 корзины, 2 оформления, 1 оплата. Где здесь
  самая большая потеря и о чём это говорит продукту? Из четырёх переходов
  интересен не самый маленький процент, а самый неожиданный.
- Событие отправляется из компонента, но знать про HTTP компонент не должен:
  посмотри, как воронка отделена от отправки через `FunnelSink`. Завтра события
  поедут в аналитику, и менять придётся одну реализацию.
- Ключ идемпотентности при оформлении генерируется на клиенте. Почему именно там,
  а не на сервере? Ответ в шаге 9.
- Токен покупателя клиент кладёт сам, а Vite в разработке раздаёт запросы по трём
  сервисам: посмотри `vite.config.ts` и подумай, что из этого в проде берёт на себя
  шлюз.
- Витрина `GET /api/v1/products` в каталоге отдаёт только опубликованные карточки
  и не требует токена: сравни с `GET /api/v1/products/my` и подумай, почему это
  два разных запроса, а не один с фильтром.
- Отдельно подумай, что делать с событиями, когда пользователь ушёл со страницы
  до отправки.
