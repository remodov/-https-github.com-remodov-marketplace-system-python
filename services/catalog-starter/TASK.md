# Шаг 2. Фильтр каталога по цене

## Что нужно сделать

Ручка `GET /products` умеет отдавать весь каталог и искать по названию.
Добавь необязательный параметр `maxPrice`:

```
GET /products?maxPrice=2000
```

С ним ручка отдаёт только товары не дороже указанной цены, отсортированные
по возрастанию цены. Без параметра поведение прежнее - весь каталог.

## Где править

Три файла в `catalog_starter/product`, в каждом стоит `# TODO шаг 2`:

| файл | что там сделать |
|---|---|
| `repository.py` | метод выборки в протоколе `ProductStore` и запрос в `SqlAlchemyProductStore` |
| `service.py` | сценарий чтения `cheaper_than` |
| `router.py` | необязательный параметр и выбор сценария |

Параметр приходит строкой; в число его превращает FastAPI по аннотации, и мусор
вроде `maxPrice=дорого` должен получить 400 с именем поля, а не пятисотку.

## Как проверить себя

```bash
pytest
```

Файл `tests/test_filter.py` красный: фильтр отсекает лишнее, дешёвое идёт первым,
граница включается (товар ровно за `maxPrice` попадает в выдачу), запрос без
параметра по-прежнему отдаёт весь каталог, а мусор в параметре даёт 400 с полем
`errors.maxPrice`. Задание сделано, когда он зелёный и не сломались пять тестов
из `test_api.py`.

## На что посмотреть по дороге

- Деньги в `Decimal`, а не во `float`: `2000` и `1999.99` должны сравниваться
  точно. `Numeric(12, 2)` в модели отдаёт `Decimal` и принимает его обратно.
- Граница `<=` против `<` - в требовании написано «не дороже», это включающее
  условие. Тест на границу существует именно потому, что здесь легко ошибиться.
- Сортировать надо на стороне базы, `order_by(Product._price)`, а не в Python
  после выборки: иначе на ста тысячах товаров в память поедет весь каталог.
- Что уходит в базу: запусти тесты с `SQL_ECHO=1` или выполни в `psql`
  `explain select * from products where price <= 2000 order by price` - по цене
  индекса нет и сортировка идёт в памяти.
